# 03_产品变现 / Product Monetization

## 1. 触发条件

当任务涉及以下内容时启用本模块：

- 变现、赚钱、商业模式、定价、客户、成交、销售、渠道、转化、复购、续费、增长、利润、成本、交付。

## 2. 变现判断的第一原则

不要先问“怎么收费”，先问：

1. 谁付钱？
2. 为什么现在付钱？
3. 付钱后得到什么明确结果？
4. 成交阻力在哪里？
5. 交付成本是否可控？
6. 是否能重复销售或长期复购？

## 3. 商业模式判断表

| 维度 | 必须判断的问题 |
|---|---|
| 付费对象 | 使用者和付款者是否一致？ |
| 付费场景 | 用户在什么具体场景下愿意付费？ |
| 痛点强度 | 是刚需、强需求、弱需求，还是兴趣需求？ |
| 替代方案 | 用户现在用什么替代方案？ |
| 成交路径 | 用户从知道到付款需要几步？ |
| 定价依据 | 按成本、效果、节省时间、情绪价值还是稀缺性定价？ |
| 毛利结构 | 单次交付成本、售后成本、时间成本是否可控？ |
| 复购逻辑 | 为什么会再次购买？ |
| 规模化 | 是否过度依赖个人能力？ |
| 长期资产 | 是否沉淀品牌、客户池、数据、内容、渠道？ |

## 4. 不成熟变现信号

出现以下情况时必须提醒风险：

- 只说“用户很多”，但没有明确谁付钱。
- 只说“市场很大”，但没有具体成交路径。
- 只说“可以卖课/会员/订阅”，但没有复购理由。
- 只追求功能完整，但没有付费触发点。
- 产品越做越复杂，交付成本越来越高。
- 依赖创始人个人精力，无法复制。

## 5. 变现优先级

优先考虑：

1. 最容易成交的小单。
2. 最能证明需求的付费验证。
3. 最低交付成本的服务或产品包。
4. 最容易复购或转介绍的场景。
5. 能沉淀长期资产的商业路径。

不要一开始就设计过重商业模式。

## 6. 默认输出结构

产品变现类任务默认输出：

1. 变现对象。
2. 付费场景。
3. 可卖的产品形态。
4. 初始定价区间或定价逻辑。
5. 成交路径。
6. 主要阻力。
7. 最小付费验证方案。
8. 不建议现在做的变现方式。
