# 06_文档沉淀 / Documentation Rules

## 1. 触发条件

当任务涉及以下内容时启用本模块：

- 文档、规则、模板、沉淀、保存、版本、变更日志、流程图、需求文档、报告结构、规则库。

## 2. 是否需要生成文件

默认判断：

- 分析、复盘、方法讨论：直接文字回答，不自动保存文件。
- 开发、原型、规则库、报告模板、可复用结构：默认生成文件。
- 两者都有可能时，优先用选择题让用户判断。

## 3. 文档结构原则

文档不是越长越好，而是要能指导纠偏。重要文档必须写清：

1. 主目标。
2. 第一用户。
3. 核心链路。
4. 不做什么。
5. 功能优先级。
6. 判断标准。
7. 前后台边界。
8. 验收标准。
9. 交付前检查清单。

## 4. 命名规则

目录和重要文件使用中文 + English：

```text
01_产品研发_ProductDevelopment.md
02_产品变现_ProductMonetization.md
```

版本文件建议：

```text
整体原则_v1.1_长期主义产品研发版.txt
产品需求文档_v0.3_ProductRequirements.md
```

## 5. 页面和文档边界

流程图、原型、页面中不要放：

- 解释性说明。
- 待确认问题。
- 决策记录。
- 给协作者看的注释。

这些内容应该放在对话、README、变更日志或决策记录中。

## 6. 默认输出结构

文档沉淀类任务默认输出：

1. 生成了什么文档。
2. 文档适用场景。
3. 是否包含版本号。
4. 是否更新变更日志。
5. 后续如何调用。
