# 08_变更日志 / Change Log Rules

## 1. 触发条件

涉及以下内容时必须记录版本或变更日志：

- 原型。
- 流程图。
- 文档。
- 规则库。
- 需求文档。
- 关键代码结构。
- 重要功能逻辑。
- 协作原则。
- 页面主链路。

## 2. 版本号规则

建议使用：

```text
v0.1 初稿
v0.2 小幅调整
v1.0 可正式使用版本
v1.1 重要优化版本
v2.0 结构重大变化版本
```

文件名可以包含版本号：

```text
Codex规则包_v1.0.zip
整体原则_v1.1_长期主义产品研发版.txt
```

## 3. 变更日志格式

每条变更记录包含：

```text
## YYYY-MM-DD vX.X

触发原因：
修改内容：
影响范围：
执行结果：
后续注意：
复核点：
```

`复核点` 用来记录：什么信号出现时，说明当前判断或规则需要重新评估。  
如果没有明确复核条件，写“暂无明确复核点，后续重要修改时重新评估”。

## 4. 不要把变更记录写进正式页面

变更记录应该放在：

- `PrincipleChangeLog.md`
- `CHANGELOG.md`
- README 的版本说明区域
- 独立决策记录文件

不要写进用户前台页面、原型页面或正式业务界面。

## 5. 原则变更的同步要求

凡是新增或修改协作原则、场景路由、交付检查、输出模板或调用方式，必须同步检查：

1. `AGENTS.md` 是否需要更新。
2. 对应 `agent-rules/` 模块是否需要更新。
3. `README.md` 或 `README_使用说明_Usage.md` 是否需要说明。
4. `MANIFEST_文件清单.md` 是否需要新增文件。
5. `PrincipleChangeLog.md` 是否记录了触发原因、修改内容、影响范围、执行结果、后续注意和复核点。
